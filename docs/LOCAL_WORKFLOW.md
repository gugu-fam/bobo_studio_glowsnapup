ローカル専用ビルド/署名/検証ワークフロー
=================================

目的: リモートへ push せずローカルだけでビルド、署名、検証、配布を完結させる運用手順。

主なコマンド:

- 依存取得・解析・テスト・アーカイブ・署名・検証（ワンコマンド）:

  ```bash
  make ci
  ```

- 署名のみ（既存アーカイブがある場合）:

  ```bash
  ./scripts/sign.sh
  ```

- 署名の検証のみ:

  ```bash
  ./scripts/verify.sh
  ```

運用上の注意:

- `archive/` と `secure/` はローカルにアーティファクトを置くための場所です。これらはリポジトリに含めないでください（既に存在する場合はコミット対象から外してください）。
- 公開鍵や検証レポートは `reports/` に保存されます。必要に応じてバックアップしてください。
- `Makefile` と `scripts/`、`.githooks/pre-push` はローカルでの自動化テンプレとして追加済みです。リモートへは push しないでください。
- pre-push フックを有効化すると `make ci` が自動実行されます。フックの有効化は手動で行ってください:

  ```bash
  chmod +x .githooks/pre-push
  ln -sf ../../.githooks/pre-push .git/hooks/pre-push
  ```

ファイルの取り扱い指針:

- アーカイブや署名済アーティファクトはリポジトリに入れない（.gitignoreに追加済）。
- 監査用の `reports/gpg_verify_*.txt` や `reports/sha256_*.txt` はローカルに保管し、必要なら別の安全なストレージに移してください。

トラブルシューティング:

- GPG 検証で一時的に不正と出る場合は、署名ファイルとアーカイブの組合せ（タイミングの差）を疑ってください。改めて `gpg --verify` を実行すると最終的に正しいことが確認できる場合があります。
